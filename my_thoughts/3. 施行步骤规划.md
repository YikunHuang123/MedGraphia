### 关键依赖链（阻塞关系）

下面是真正的串行阻塞链——后一步完全依赖前一步的输出，无法并行：

```
数据获取 → 解析 → 分块 → NER → 实体链接 → 关系抽取 → Neo4j写入
                           ↘
                            嵌入 → Qdrant写入

只有 Neo4j + Qdrant 都写入完成后，才能启动在线查询管道
```

可并行开发的部分（不互相阻塞）：

```
嵌入器 ──────────────┐  可与NER/实体链接同步开发
FastAPI基础框架 ────┤  可在离线管道完成前先搭架子（用假数据测试）
Streamlit UI ───────┘  可用mock API先跑通界面
```

## 二、分阶段开发计划

总体原则： **先跑通英文单域 lite 模式，再扩语言，最后上企业特性** 。每个 Phase 都要有可运行的产物，不做"完成后才能跑"的大跃进。

---

**目标：** 让团队（或你自己）能运行整个空壳，跑通配置、连接、健康检查。

|Docker Compose| `[docker-compose.lite.yml](docker-compose.lite.yml)`：Neo 4 j + Qdrant（或 Chroma）+ API 容器|
|领域模型| `[domain.py](domain.py)`：Entity、Relation、Chunk、Session、Message dataclass/Pydantic|
|健康检查| `[api/health.py](api/health.py)`：`/health/live` + `/health/ready`（检查 Neo 4 j + Qdrant 连通）|

- Neo 4 j Browser 能看到空图谱，Qdrant Dashboard 可访问

**预计时间：** 3–5 天

### Phase 1：数据获取 + 文档解析

**目标：** 从授权数据源拉到原始文档，解析成干净的结构化文本。

|任务|具体内容|
|---|---|
|PubMed 连接器| `[data/pubmed.py](data/pubmed.py)`：E-utilities API，按关键词+时间范围+引用量抓摘要，支持 `--limit` 参数|
|DrugBank 连接器| `[data/drugbank.py](data/drugbank.py)`：解析官方 XML 导出（学术版，需注册申请）|
|EMA SmPC 连接器| `[data/ema_smpc.py](data/ema_smpc.py)`：下载欧洲药品说明书 XML 批量包|
|Docling 解析器| `[ingestion/parsers/docling_parser.py](ingestion/parsers/docling_parser.py)`：PDF → DoclingDocument JSON，提取章节树、表格|
|OCR 兜底| `[ingestion/parsers/ocr_parser.py](ingestion/parsers/ocr_parser.py)`：Tesseract fallback，用于扫描版|
|获取脚本| `[scripts/fetch_pubmed.py](scripts/fetch_pubmed.py)`：命令行工具，输入 `--domain t2dm --limit 200`，输出 `data/raw/` 下的 JSON|

**完成标准：**

- `python [scripts/fetch_pubmed.py](scripts/fetch_pubmed.py) --domain t2dm --limit 200` 下载 200 篇摘要到本地
- 对一个真实 PDF（如某药品说明书），Docling 能输出带 `section_path` 元数据的 JSON
- 单元测试：`[tests/test_parsers.py](tests/test_parsers.py)` 通过

**预计时间：** 5–7 天

---

### Phase 2：分块与归一化

**目标：** 把解析后的文档切成带结构元数据的 chunk，不用固定 512 token。

|任务|具体内容|
|---|---|
|Section-aware 分块| `[ingestion/chunker.py](ingestion/chunker.py)`：按 Docling 章节树做 anchor-aware 切割，每块保存 `section_path`、`doc_id`、`page`、`char_offset` |
|归一化器| `[ingestion/normalizer.py](ingestion/normalizer.py)`：把 `"bid"` / `"2 x täglich"` / `"每日两次"` 统一成 FHIR Timing JSON；单位换算|
|Chunk 写入 Neo 4 j|在 `[graph/queries.py](graph/queries.py)` 中加 `create_chunk()` Cypher；Chunk 作为独立节点，通过 `FROM_DOC` 边连接到文档节点|

**完成标准：**

- 200 篇 PubMed 摘要经过分块后，每块平均 200–400 token，`section_path` 不为空
- `normalizer` 对测试集（20 条不同语言剂量表达）归一化准确率 > 90%
- Neo 4 j 中能看到 Chunk 节点

**预计时间：** 4–6 天

---

### Phase 3：医学 NER + 实体链接

**目标：** 从 chunk 文本中识别医学实体，将其链接到 UMLS CUI。这是整个图谱质量的关键。

|任务|具体内容|
|---|---|
|UMLS 子集导入|用 MetamorphoSys 导出三词表（SNOMED CT + RxNorm + MeSH）仅英文；`[scripts/load_umls_subset.py](scripts/load_umls_subset.py)` 导入 Neo 4 j|
|GLiNER-biomed 粗筛| `[ingestion/ner/gliner_ner.py](ingestion/ner/gliner_ner.py)`：零样本粗筛，返回候选 span + 粗类别（Disease/Drug/Symptom/Gene）|
|BioBERT 精筛（英文）| `[ingestion/ner/biobert_ner.py](ingestion/ner/biobert_ner.py)`：BIOES 标注微调模型，对粗筛结果精化边界|
|SapBERT 实体链接| `[ingestion/entity_linker.py](ingestion/entity_linker.py)`：BM 25 召回 top-50 UMLS 候选 → SapBERT cross-encoder 重排 → 阈值过滤，低置信度标注 `UNLINKED` |
|结果写入 Neo 4 j| `[graph/queries.py](graph/queries.py)`：`merge_entity(cui, label, type)`；实体与 Chunk 通过 `MENTIONED_IN` 边连接|

**完成标准：**

- 在 50 篇测试文档上：NER F 1 > 0.72（BioBERT PubMed 基准约 0.85，但冷启动实际稍低）
- 实体链接命中率（top-1 CUI 正确）> 65%（可逐步提升）
- Neo 4 j 中：Disease、Drug、Symptom 节点出现，节点带 `cui` 属性
- `[tests/test_ner_pipeline.py](tests/test_ner_pipeline.py)` + `[tests/test_entity_linking.py](tests/test_entity_linking.py)` 通过

**预计时间：** 7–10 天（NER 模型下载 + 调优是主要耗时）

---

### Phase 4：关系抽取与图谱构建

**目标：** 让 Neo 4 j 图谱从"只有节点"变成"有语义关系的知识图谱"。

|任务|具体内容|
|---|---|
|关系抽取| `[ingestion/relation_extractor.py](ingestion/relation_extractor.py)`：给 LLM 一个 chunk + chunk 内的实体列表，要求只输出 schema 内关系（TREATS / CAUSES / INTERACTS_WITH / DOSAGE_FOR / SYMPTOM_OF / COMPLICATION_OF / CODED_AS / CONTRAINDICATED_IN）；用结构化输出（Pydantic）|
|LLM Provider 基础版| `[generation/providers/deepseek_provider.py](generation/providers/deepseek_provider.py)` 或 `[local_provider.py](local_provider.py)`（Ollama）；`[generation/litellm_gateway.py](generation/litellm_gateway.py)` 包一层，统一记录调用|
|关系写入 Neo 4 j| `[graph/queries.py](graph/queries.py)`：`create_relation()`，每条边存 `evidence_text`、`chunk_id`、`confidence`、`source_version` |
|Leiden 社区发现| `[ingestion/community_builder.py](ingestion/community_builder.py)`：调用 `graspologic` 或 `cdlib` 的 Leiden 实现；对 Neo 4 j 图做社区划分；调用 LLM 生成每个社区的 150 字摘要；摘要存为 `Community` 节点|
|构建管道串联| `[ingestion/pipeline.py](ingestion/pipeline.py)`：把 Phase 1–4 串成一个 Prefect Flow（先不用 Airflow，Prefect 更轻量）|

**完成标准：**

- 对 T 2 DM 子域（200 摘要 + 30 药品说明书）跑完整管道：Neo 4 j 出现 > 5000 个节点、> 20000 条关系
- Leiden 社区摘要可读，能描述出"二甲双胍相关心血管保护"之类的主题
- 整个离线管道 `[scripts/build_graph.py](scripts/build_graph.py) --domain t2dm` 可以一键跑完
- 构建成本（API token 费用）< 50 RMB（lite 模式目标）

**预计时间：** 8–12 天

---

### Phase 5：嵌入 + 向量索引

**目标：** 所有 chunk 都能被向量检索到，且支持 dense + sparse 混合检索。

|任务|具体内容|
|---|---|
|BGE-M 3 嵌入器| `[ingestion/embedder.py](ingestion/embedder.py)`：调用 `FlagEmbedding` 库的 BGE-M 3，批量输出 dense + sparse（可选 ColBERT）|
|Qdrant 写入| `[vector/qdrant_store.py](vector/qdrant_store.py)`：`upsert_chunks()`，dense + sparse 双向量写入同一个 Collection|
|实体嵌入|用 SapBERT 对 Neo 4 j 实体节点嵌入，写入第二个 Qdrant Collection（用于实体级相似检索）|
|Chroma fallback| `[vector/chroma_store.py](vector/chroma_store.py)`：仅 dense，用于完全无 GPU 环境|

**完成标准：**

- `GET /health/ready` 中 Qdrant collection 状态 = `green`
- 手工测试：向量检索"metformin renal contraindication"能召回相关 chunk（top-5 里有正确答案）
- dense + sparse hybrid 比纯 dense 的 recall@10 提升 > 5%（在小测试集上验证）

**预计时间：** 4–6 天（BGE-M 3 本地推理如果没 GPU 会较慢，可用 Ollama `nomic-embed-text` 先临时替代）

### Phase 6：在线查询管道——三路检索 + 融合

**目标：** 给定一个用户问题，能从三条路径召回相关上下文并排好序。这是 GraphRAG 与普通 RAG 的本质差异点。

|任务|具体内容|
|---|---|
|查询侧 NER + 实体链接|复用 Phase 3 的模块，对查询文本提取实体 + 链接到 CUI（轻量化，只做粗筛）|
|LangGraph 路由器| `[retrieval/router.py](retrieval/router.py)`：定义 5 种查询类型的分类逻辑（rule-based 先做，后续可换 LLM classifier）|
|图检索器| `[retrieval/graph_retriever.py](retrieval/graph_retriever.py)`：把查询 CUI 作为起点，Cypher 做 1–2 跳子图展开；输出 (entity, relation, neighbor) 三元组列表|
|向量检索器| `[retrieval/vector_retriever.py](retrieval/vector_retriever.py)`：BGE-M 3 对查询编码 → Qdrant hybrid search（dense + sparse）|
|社区检索器| `[retrieval/community_retriever.py](retrieval/community_retriever.py)`：对 Community 摘要节点做向量检索，用于 global QA 场景|
|RRF 融合| `[retrieval/fusion.py](retrieval/fusion.py)`：三路结果 Reciprocal Rank Fusion|
|重排器| `[retrieval/reranker.py](retrieval/reranker.py)`：bge-reranker-v 2-m 3 cross-encoder，top-20 → top-5|

**完成标准：**

- 单元测试 `[tests/test_retrieval.py](tests/test_retrieval.py)`：10 个测试问题，图检索 + 向量检索各自 recall@5 > 0.5
- RRF 融合后 recall@5 > 0.65（高于单路）
- 重排后 NDCG@5 有提升
- 整个检索链 P 50 延迟 < 3 s（在本地机器上）

**预计时间：** 8–10 天

### Phase 7：LLM 生成层 + 安全护栏

**目标：** 把检索到的上下文交给 LLM 生成答案，注入引用，通过安全过滤。

|任务|具体内容|
|---|---|
|LLM Provider 完整版|补全所有 providers：OpenAI、Anthropic、DeepSeek、Ollama；`[litellm_gateway.py](litellm_gateway.py)` 统一代理|
|LLM 路由器| `[generation/llm_router.py](generation/llm_router.py)`：按场景（患者 FAQ → 小模型；临床决策 → 大模型）和语言路由|
|DSPy Prompt 模块| `[generation/prompts.py](generation/prompts.py)`：为每种查询场景（5 种）+ 每种语言（EN/ZH/DE）写 DSPy TypedPredictor；强制输出格式包含 `citations: list[int]` |
|引用注入| `[generation/citation.py](generation/citation.py)`：从 LLM 输出的 `[1][2]` 标记反查对应 chunk，构造 `Citation` 对象（含 section_path、source_version）|
|安全护栏| `[generation/guardrails.py](generation/guardrails.py)`：Llama Guard 4（或先用 rule-based 黑名单兜底）做输入过滤；输出检查是否触发"诊断/处方"规则；RAGAS faithfulness 在线评分（低于阈值拒绝）|

**完成标准：**

- 端到端 Python 函数 `run_query("What drug interactions does metformin have?")` 返回带 citations 的答案
- 护栏正确拒绝"帮我开药方"类请求
- RAGAS faithfulness > 0.75 on 20 test Q&A
- 引用能精确对应到 chunk，chunk 有 `section_path`

**预计时间：** 7–10 天

## 四、高风险项预警

|风险点|原因|缓解策略|
|---|---|---|
| **实体链接质量** |SapBERT 对中文/德文医学短语链接率不稳定|Phase 3 结束后做人工抽检；低置信度标注 UNLINKED，不写入图谱|
| **LLM 关系抽取成本** |每个 chunk 都调用 LLM，500 篇文档可能超出预算|先用 DeepSeek/Qwen-Turbo API（最便宜）；不合格 chunk 跳过|
| **BGE-M 3 本地推理速度** |无 GPU 时 CPU 推理非常慢（每批 30 s+）|Lite 模式用 `nomic-embed-text`（Ollama）临时替代，Phase 5 完成后再切回|
| **Neo 4 j 内存** |数据量一旦超出 `page_cache` 性能急剧下降|Lite 模式严格限制域和文档数量；监控 `[neo4j.conf](neo4j.conf)` 中 `dbms.memory.pagecache.size` |
| **社区发现图爆炸** |Leiden 在稠密图上可能生成数百个社区|限制最小社区大小（`min_community_size=5`）；社区摘要异步生成|

**建议的第一步：** 从 Phase 0 开始，在第一天让 `docker compose up` + `/health/ready` 跑通。有一个可以运行的空壳，后续所有 Phase 都是往里填内容——这比先写业务逻辑再配环境要稳得多。
